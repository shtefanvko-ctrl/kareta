# KARETA.KZ — R188.5.5.6.84.86

## Messaging Core / Telegram + WhatsApp — Stage 1

База: `R188.5.5.6.84.85`.

### Что внедрено

- KARETA Chat остаётся источником истины для истории переписки.
- Telegram Bot API и WhatsApp Business Cloud API подключаются как внешние каналы доставки/ответа.
- Исходящие внешние сообщения ставятся в DB-очередь; сетевой запрос к провайдеру не блокирует `messages.add`.
- Входящие Telegram/WhatsApp webhook-события дедуплицируются и сохраняются в соответствующий KARETA chat.
- Привязка канала к пользователю выполняется одноразовым токеном, в БД хранится только SHA-256 hash токена.
- Настройки каналов доступны и клиенту, и мастеру: основной канал, сообщения, заявки, согласования, расписание, внешние ответы.
- Deep-link `#/chats?chatId=...` открывает только чат, доступный текущему пользователю.
- Telegram webhook проверяет `X-Telegram-Bot-Api-Secret-Token`.
- WhatsApp webhook проверяет `X-Hub-Signature-256` и поддерживает verification handshake.
- WhatsApp свободные исходящие сообщения блокируются вне 24-часового service window; очередь не отправляет их незаконно.
- `config.private.php` и provider credentials в релиз не входят.

### Production schema policy

Runtime DDL по умолчанию отключён. Перед включением провайдеров один раз выполнить:

```bash
php tools/messaging_schema_install.php
```

`KARETA_MESSAGING_AUTO_SCHEMA` / `messaging_auto_schema` по умолчанию `false` и в production должен оставаться `false`.

### Provider configuration

Использовать переменные окружения либо `config.private.php` на сервере.

Telegram:
- `KARETA_TELEGRAM_ENABLED`
- `KARETA_TELEGRAM_BOT_TOKEN`
- `KARETA_TELEGRAM_BOT_USERNAME`
- `KARETA_TELEGRAM_WEBHOOK_SECRET`
- webhook: `/api/webhooks/telegram.php`

WhatsApp:
- `KARETA_WHATSAPP_ENABLED`
- `KARETA_WHATSAPP_ACCESS_TOKEN`
- `KARETA_WHATSAPP_PHONE_NUMBER_ID`
- `KARETA_WHATSAPP_BUSINESS_PHONE`
- `KARETA_WHATSAPP_VERIFY_TOKEN`
- `KARETA_WHATSAPP_APP_SECRET`
- webhook: `/api/webhooks/whatsapp.php`

### Worker

Однократная обработка очереди:

```bash
php tools/messaging_worker.php
```

Постоянный worker:

```bash
php tools/messaging_worker.php --watch --interval=2
```

На production предпочтителен supervisor/systemd/cron, а не запуск worker из HTTP request.

# KARETA — Professional Services Safe Candidate v1

Дата: 2026-10-21. Ветка: `feat/professional-service-catalog-preview-20261021`. Основа: актуальный удалённый `origin/staging` (c150a0f) в момент создания. Развёртывание не выполнялось.

## Статус

**DRAFT / read-only / NOT DEPLOYED.** Внесено 103 кандидата профессиональных операций в `storage/catalog/professional_services_draft.json`. Они имеют ID с префиксом `pro_` и связи с существующими профессиями и предложенным оборудованием. По умолчанию ни одна операция не является опубликованной, доступной для записи, разрешённой для автоматического подключения или подтверждённой экспертно. Нет искусственных цен. Действующие `service_catalog`, `service_categories`, `service_offers`, `master_professions.json`, `master_equipment.json`, `services.json`, `master_service_advisories.json` не изменены.

## Предварительная проверка

`php tools/test_professional_services_draft.php`

Проверяет: существующие 109 операций без изменений; 109 рекомендаций без изменений; все 20 категорий; уникальность ID и названий относительно имеющегося каталога; ссылки на существующие профессии и оборудование; выключенные статусы публикации, подбора и бронирования.

## Порядок последующего безопасного переноса

1. Получить экспертное подтверждение состава услуг/профессий/оборудования, включая технологии ремонта, безопасность HV и требования к квалификации.
2. Проверить актуальный runtime staging и DB read-only: версии, фактические `service_catalog`, `service_categories`, `service_offers`, `orders`, манифест миграций и локальные dirty-изменения.
3. Подготовить отдельно **additive-only** миграцию для одобренных услуг (не менять существующие ID и цены, не деактивировать старые записи) с возможностью повтора, отката и dry-run.
4. Новые услуги вводить неактивными и без автоматических предложений платформы; публикация только после `serviceOffers.save` мастером/СТО. Отдельно обеспечить отображение кандидатов на клиентской стороне только после активации исполнителем.
5. Добавить на странице «Мои услуги» **необязательную** фильтрацию рекомендованных работ по выбранным профессиям; полный каталог оставлять доступным; не менять шапку, нижнее меню, канон и роль/capabilities.
6. Затем выполнить поисковый индекс по опубликованным услугам (а не по имени мастера), синонимам и заявкам с сохранением `serviceId` по всему процессу.
7. Только после тестов и контрольных сценариев провести feature-flag rollout на staging. Продакшн не трогать.

## Подводные камни

- `kareta_service_catalog_import()` архивирует отсутствующие в источнике записи и публикует `platform`-предложения; просто вписывать новое в `services.json` без исправления импорта небезопасно.
- `master_onboarding.php` при завершении переписывает активные предложения; повторное редактирование профессии/оборудования не должно сбрасывать `service_offers`.
- Текущие данные рекомендательных связей содержат `expert_review=NOT_RUN`, `ranking_impact=disabled`, `matching_usage=disabled` — не включать hard-filter.
- Рабочий каталог staging в момент аудита имел множество незакоммиченных изменений. Не подменять/чистить его автоматически.

## Следующая точка приёмки

До активации сервисов требуется отдельно проверить, что профессиональные операции добавляются **без удаления, изменения или публикации** существующих предложений, а пользовательский поиск не выдаёт кандидатов без опубликованного `service_offers`.

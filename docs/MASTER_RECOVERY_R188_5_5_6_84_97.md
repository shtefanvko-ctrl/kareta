# KARETA.KZ R188.5.5.6.84.97 — восстановление первого входа мастера

Основа: полный предоставленный архив R188.5.5.6.84.95 (NO_ASSETS).
Это завершённый пакет исправлений первого входа, а не заявление о завершении всего кабинета мастера.

## Что исправлено

- Проверка обязательной анкеты перед переходом после регистрации и входа существующего пользователя.
- Проверка страницы рабочего места, низкоуровневого API-клиента и прямых вызовов db.php. Незавершённый профиль получает HTTP 409, error=master_onboarding_required, code=MASTER_ONBOARDING_REQUIRED и маршрут анкеты.
- Сохранённый sessionStorage-статус не открывает рабочие данные без ответа сервера. Устаревший ответ другого контекста не открывает текущий профиль.
- Сервер сверяет master_onboarding_state и lifecycle профиля, поддерживая payload_json схемы 129 и отдельные столбцы, если они уже существуют.
- Повтор загрузки каталога и skeleton; пагинация больше не обрезает результат до первых 40 услуг; отменённый старый запрос не сбрасывает новый.
- Черновик сохраняется последовательно, с expectedRevision. Завершение анкеты ждёт очередь сохранений. Ответ saveDraft возвращает именно ревизию выполненной записи.
- Конфликт вкладок требует явного выбора локального или серверного черновика. Данные не объединяются молча с восстановлением удалённых услуг.
- Восстановление связи, storage/BroadcastChannel и возврат на вкладку сверяют серверную ревизию. Ошибки сети сохраняют локальный черновик.
- Предпросмотр фото с центральной квадратной обрезкой и масштабом, загрузка JPEG, удаление аватара. Исходные изображения и canvas не пишутся в localStorage.
- Необязательный адаптер KaretaAddressProvider.suggest для подсказок адреса; при отсутствии провайдера работает ручной ввод. Внешний геосервис не добавлен.
- Исправлены фокус и позиция курсора при вводе имени/описания, повтор после ошибки загрузки анкеты, принятие пустых координат как (0,0).
- Автообновление рабочего места не перерисовывает открытый диалог или выполняемое действие; настройка «Выкл.» остаётся выключенной.
- Пересобраны используемые boot bundles; версия ресурсов и Service Worker — .84.97.

## Исходный baseline и миграции

Runtime PHP-манифест и config.php исходной сборки закреплены на 129. Это подтверждено PATCH_R188_5_5_6_84_86.md. JSON-манифест был устаревшей копией на 133: он приведён к фактическим 129 миграциям. Миграции 130–133 не включены в исполнение, исторические SQL-файлы не изменялись. Новая схема для этих исправлений не нужна.

index.php не изменён ни на байт относительно входного ZIP. Фактический SHA-256: 5e3dbc84e0ff808dd023d490399677f7ff1616d3c7bebaeb1bfab462d0854d26. Старый ожидаемый hash в release gate / freeze manifest / тесте .84.79 был от другой сборки; он согласован с предоставленным файлом. Остальные защищённые файлы не редактировались.

Тест .84.29 учитывает существующую с .84.85 обёртку boot-profiler вокруг awaited onboarding gate. Тест .84.95 теперь проверяет версию не ниже .95 и равенство asset/SW вместо требования ровно .95.
Обязательные .84.18, .84.29 и новый поведенческий .84.97 включены в tools/release_gate.php.

## Что остаётся / три следующих шага

1. На PHP 8.1+ / MySQL стенде выполнить `php tools/release_gate.php --package=no-assets`, затем проверить два входа (новый/существующий мастер), незавершённую анкету и прямые запросы к db.php. В браузере 320/390/768/1440 px проверить ввод, фото, offline, две вкладки и возврат в рабочее место.
2. После зелёного baseline выполнить пункты 3–6 текущей очереди: единая модель города и зон, mobile без адреса/координат/radius, fixed с подтверждённой мастерской, both с адресом и зонами; серверная валидация, поиск и контролируемый dry-run старых данных. Текущий интерфейс origin/radius в этом пакете ещё сохранён.
3. Завершить пункты 7–10: состояния сохранения «Моих услуг», мобильная биржа, связка главная → заявка → ремонт/пауза, затем полная матрица и итоговый ZIP.

Основание порядка: docs/KARETA_TASK_QUEUE_AFTER_R188_5_5_6_84_94.md прямо запрещает переход к изменениям доменной модели до зелёного release gate. Этот пакет закрывает восстановление baseline в доступной среде; оставшиеся проверки и функции перечислены явно.

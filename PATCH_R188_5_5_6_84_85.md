# R188.5.5.6.84.85 — Boot Profiler

Base: `R188.5.5.6.84.84`
Target: `R188.5.5.6.84.85`
Mode: overlay patch, NO_ASSETS compatible.

## Цель

Следующий этап после сокращения CSS/JS/manifest/session waterfall — измерять cold boot по фактическим этапам и больше не оптимизировать запуск по визуальному ощущению.

Профилировщик встроен в `js/next/runtime_logger.js`, который и так является первым boot script. Дополнительного HTTP-запроса для профайлера нет: atomic boot остаётся на 11 JS transport requests.

## Что измеряется

- HTML response / DOM timing через Navigation Timing;
- critical `runtime_boot_bundle.css` через Resource Timing;
- atomic/route `asset_manifest.php`;
- transport каждого boot JS;
- фактическое время выполнения пяти generated boot bundles;
- общая session wave;
- отдельно DB/version guard, Identity current и legacy session;
- initial route prewarm / final route load;
- version parity;
- master onboarding gate;
- route render;
- first render;
- следующий animation frame после первого render;
- момент `interactive`;
- FCP/FP, когда браузер их предоставляет;
- Long Tasks на main thread через `PerformanceObserver`.

## Вывод

После успешного cold boot в консоли появляется:

`[KARETA][boot.profile] <N>ms · <route>`

Полный снимок доступен как:

- `window.KaretaBootProfile`
- `window.KaretaBootProfiler.snapshot()`
- `window.KaretaBootProfiler.export()`

Последний профиль также сохраняется в `sessionStorage` под `kareta_boot_profile_v1` и отправляется в существующий runtime-log как событие `boot.profile`.

Профиль не сохраняет OTP, cookie, authorization/token/password/code metadata.

## Bundle execution timing

`tools/build_boot_js_bundles.js` теперь добавляет только измерительные start/end markers вокруг generated bundle, сохраняя byte-for-byte порядок canonical source modules внутри каждой группы. `--check` по-прежнему гарантирует, что generated bundles не устарели.

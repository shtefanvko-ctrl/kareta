# R188.5.5.6.84.81 — Critical CSS Split / Route Visual Runtime

## Problem

The `.84.80` single-request CSS bootstrap removed the request storm, but `css/runtime_boot_bundle.css` still contained route-only visual layers for Community, Masters, Details, Parts, STO, Seller, Cabinet and professional Master surfaces. The browser therefore downloaded and parsed about 1.28 MB of raw CSS before the first useful frame, even when the user opened Home or onboarding.

## Change

- Kept exactly one eager stylesheet request: `css/runtime_boot_bundle.css`.
- Reduced the eager bundle from approximately 1.28 MB to 825,401 bytes.
- Moved route-only layers into 15 files under `css/routes/`.
- Added style-only route bundles to `kareta_route_asset_plan()`; the existing `KaretaRouteAssetLoader` loads them before route render.
- Kept the old route-specific override files (`client_cabinet.css`, `client_work_order_v2.css`, master workspace CSS, etc.) after the extracted base CSS.
- Added `css/routes/client_guard_postlude.css`. It re-applies only the historical late responsive/geometry guards before the existing route overrides. This prevents the CSS split from changing client width/mobile/viewport precedence.
- Preserved the original `Details -> Parts` cascade for product detail routes.
- Kept `request.css` and `client_request_garage.css` eager because static selector analysis found many intentional overrides from `kflow_windows.css`; extracting them would reverse that cascade.
- Kept `index.php` and `js/next/smart_action_hub.js` unchanged.

## Measured result

- `.84.80` eager CSS raw size: ~1.28 MB.
- `.84.81` eager CSS raw size: 825,401 bytes.
- Raw eager CSS reduction: ~35.5%.
- gzip-equivalent reduction in local measurement: ~34.4%.
- Eager CSS requests: still 1.
- Route-lazy CSS asset paths: 46.

## Regression protection

Added `tools/test_critical_css_split_84_81.js` which verifies:

- the critical CSS size ceiling;
- extracted source markers are absent from eager CSS and present in route bundles;
- route CSS files are registered and parseable;
- product/community/work-order/cabinet/master/finance CSS order;
- the client geometry postlude source order;
- version parity;
- no unresolved relative `url()` paths.

Historical `.84.67`, `.84.68`, `.84.69`, `.84.72` and `.84.80` tests were changed only where they incorrectly froze the old CSS mode/count/version instead of testing the original invariant.

# KARETA.KZ — R188.5.5.6.84.87

## Telegram Live Actions — Stage 2

База: `R188.5.5.6.84.86`.

### Что внедрено

- Внутренние KARETA notifications теперь могут асинхронно доставляться через основной внешний канал пользователя (`Telegram` / `WhatsApp`) с учётом `notifyOrders`, `notifyApprovals`, `notifySchedule`, `notifyMessages`.
- `message.new` не дублируется: обычный KARETA Chat по-прежнему использует отдельный Messaging fan-out из `.84.86`.
- Telegram получает интерактивные карточки для Мастера:
  - `Принять заявку`;
  - `Пропустить` (скрывает заявку из Биржи конкретного Мастера);
  - `Предложить цену` (deep-link в быстрый отклик Биржи);
  - `Начать диагностику` для назначенного заказа на этапе `intake`;
  - `Завершить работы` на этапе `in_progress`;
  - `Открыть KARETA` / `Открыть заказ KARETA`.
- WhatsApp получает те же системные order/approval/schedule notifications как текст + deep-link KARETA, но без state-changing кнопок на этом этапе.
- Клиент после принятия заявки Мастером из Telegram получает обычное KARETA notification; если у клиента включён внешний основной канал, событие также попадает в его Messaging queue.

### Безопасность Live Actions

Telegram `callback_data` не содержит `orderId`, роль или имя API-action. Кнопка несёт только короткий opaque token вида `ka:<random>`.

На сервере:

1. token хранится только как SHA-256 hash;
2. token привязан к KARETA `user_id`, каналу, action и entity;
3. TTL — 15 минут для рабочих карточек;
4. после успешного действия token помечается `used_at`;
5. webhook повторно сопоставляет Telegram user с KARETA account;
6. MASTER context разрешается через Identity Core, а не через отсутствующую webhook session;
7. action проверяет capability (`requests.respond` либо `work_orders.update_status`);
8. order ownership/status проверяются заново в момент нажатия;
9. принятие заявки использует row lock, race guard и тарифные лимиты;
10. workflow actions проходят через существующий `sto_workflow_engine`, поэтому обязательные checklist/timer requirements не обходятся.

Если у заявки отсутствуют корректные дата/время или указанное время уже прошло, Telegram **не придумывает время за пользователя** — предлагает открыть заявку в KARETA.

### Обновление Messaging schema

`.84.87` добавляет таблицу `messaging_action_tokens`. Runtime DDL остаётся выключенным.

После установки патча выполнить один раз:

```bash
php tools/messaging_schema_install.php
```

Команда идемпотентна и также проверяет остальные Messaging tables из `.84.86`.

### Production worker

Остаётся тот же worker:

```bash
php tools/messaging_worker.php --watch --interval=2
```

Без worker обычные KARETA Chat/Notifications работают, но внешняя доставка будет оставаться в очереди.

### Инварианты

- `index.php` не изменён.
- `js/next/smart_action_hub.js` не изменён.
- `config.private.php` не входит в release package.
- Runtime auto-migration не включается.
- Asset/SW release: `188.5.5.6.84.87`.
- Messaging остаётся fail-soft относительно основного KARETA UI/API: отказ внешнего провайдера не блокирует создание внутреннего notification/message.

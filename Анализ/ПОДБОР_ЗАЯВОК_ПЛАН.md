## Правила принятия решения

| Признак | Значение для подбора |
| --- | --- |
| Услуга выбрана мастером | Первичная заявленная готовность; не автоматическое подтверждение квалификации |
| Квалификация проверена | Отдельное доказательство со статусом, источником и датой; способ проверки ещё нужно определить |
| Профессия | Помогает настроить профиль и предложить услуги; не включает их молча |
| Оборудование «Есть» | Самостоятельное заявление о наличии; проверять необходимые возможности конкретной модели |
| «В СТО» / «Арендую» | Условный доступ; подтвердить место, время и доступность для конкретной заявки |
| «Нужно купить» | Не считать доступным для выполнения заявки |
| Оборудование не указано | Не равно отсутствию; не исключать мастера без утверждённого обязательного требования |
| Неизвестен материал / симптом / задача | Уточнение кнопками; не угадывать диагноз |
| Связь инструмента с услугой в черновике | Подсказка, не жёсткое ограничение |

Все требования к инструментам в service_links.json пока recommendation_not_hard_requirement. Перед жёстким исключением мастеров эксперт должен описать необходимые возможности, альтернативы и подтверждение доступа. Название модели само по себе не доказывает пригодность или навык.

## Запросы и подобные формулировки

Все примеры ниже — гипотезы из query_dictionary.json, не частотность реального спроса.

| Формулировка | Что выяснить | Результат |
| --- | --- | --- |
| «Сварщик», «сварка» | Кнопки: порог/арка, выхлоп, деталь авто, ворота/трубы; затем материал | Автоуслуга либо отдельное сообщение о выходе за текущий авто-контекст |
| «Не заводится» | Стартер крутит / не крутит / не знаю; место и выезд | engine_diag, electric_diag, fuel_diag как варианты диагностики, не готовый диагноз |
| «Машина троит» | Когда проявляется, тип двигателя; неизвестное разрешено | engine_diag / fuel_diag; не назначать замену детали автоматически |
| «Аккумулятор садится» | На стоянке / при движении / не знаю | leak_current / generator_repair как варианты проверки |
| «Не крутит стартер» | Питание/симптом уточняются без вывода о неисправной детали | starter_repair / electric_diag |
| «Ремонт проводки» | Локальная проблема, автомобиль, место работ | wiring_repair |
| «Порог / арка», «выхлоп» | Материал и объём работ | threshold_welding / exhaust_repair; оборудование проверяется отдельно |

Для синонимов хранить query ID, существующий service ID, уточнение, источник формулировки и статус. Бытовые слова из диалогов нельзя автоматически считать рыночным спросом. Расширение на «ворота/трубы» требует отдельного продуктового решения, а не добавления копий автоуслуг.

## Объяснение и условия подбора

Предложение ответа backend (проект контракта, пока не реализован): существующая заявка + причины совпадения + условия, требующие подтверждения + версия правила. Примеры человекочитаемых причин: «Вы выбрали ремонт проводки», «Заявка допускает выезд», «Доступ к инструменту нужно подтвердить». Не выводить процент как подтверждение профессиональной компетенции.

Обязательные фильтры и признаки ранжирования разделить. Сначала соблюдать права доступа, выбранные услуги и утверждённые требования; затем учитывать географию, время, режим работ, загрузку и предпочтения. Неполный профиль не должен незаметно становиться отрицательным сигналом.

## Аналитика — определения

| Показатель | Определение | Необходимые события |
| --- | --- | --- |
| Доля пустой выдачи | Завершённые поиски с 0 результатов / все завершённые поиски | search_completed; при нулевом знаменателе значение отсутствует |
| Доля уточнений | Поиски с уточнением / завершённые поиски | clarification_shown/selected, search_completed |
| Отклик после показа | Уникальные пары мастер–заявка с откликом / показанные пары | request_impression, response_submitted |
| Принятие после отклика | Уникальные принятые пары / пары с откликом | response_submitted, request_accepted |
| Жалоба на несоответствие | Уникальные пары с отметкой «Не моя услуга» / показанные пары | mismatch_reported |
| Недостающая услуга | Неразрешённые запросы после уточнения, сгруппированные вручную | unresolved_search_reviewed |

Перед реализацией проверить существующий analytics producer и правила доступа. Предложенные имена событий — план, не подключённый трекинг. У каждого события нужны ID попытки, время, версия правил, контекст и разрешённые измерения. Повторы дедуплицировать. Телефон, VIN, переписку и свободный текст с персональными данными в отчёт о спросе не включать по умолчанию. Не делать рынок или карту спроса публично из единичных персональных событий.

## Приёмочные сценарии интеграции

1. «Сварщик» не выбирает сварку ворот как автоуслугу без уточнения.
2. Наличие сварочного аппарата не подтверждает навык работы с алюминием.
3. «Нужно купить» не проходит как доступный инструмент.
4. Доступ в СТО или аренда не равны гарантированной доступности в нужное время.
5. Одинаковый смысл в разных формулировках ведёт к тем же service ID.
6. При переходе Master → Client → другой Master поздние ответы не меняют новый профиль.
7. Несохранённый черновик не участвует в подборе вместо подтверждённого состояния сервера.
8. Сохранённая версия — основная при конфликте; применение черновика только явно.
9. Пустая выдача отличается от ошибки API и от отказа доступа.
10. Необработанное уточнение не превращается в уверенный диагноз.
11. Выключение нового подбора восстанавливает прежнюю выдачу и сохраняет настройки профиля.
12. События и объяснения соответствуют той версии правил, которая дала результат.

# Анализ KARETA — контрольная точка 01.10.2026

## Дополнительное задание: услуги, оборудование и подходящие заявки

Результат текущей работы: проверяемый план, расширение существующего справочника без копий, исследование предложений оборудования, тематический набор иконок и аудит страниц. Основной продуктовый приоритет — веб-версия. Android требует отдельной проверки совместимости; изменения нативного проекта этим заданием не запрошены.

## Решения пользователя

- Мастер выбирает оказываемые услуги, профессии/специализации и оборудование.
- Подбор заявок учитывает подтверждённые услуги, специализацию, возможности оборудования и условия работы.
- Мастер видит, по каким запросам попадают заявки и почему конкретная заявка показана.
- Максимум выбора через кнопки, категории, карточки и переключатели; основной сценарий услуг/оборудования без ручного ввода.
- Для оборудования отдельная кнопка. Исследовать предложения магазинов Усть-Каменогорска: товар, продавец, цена, валюта, источник, дата проверки и опубликованное наличие.
- Для карточек нужны картинки, иконки и короткие названия. На телефоне компактно; на планшете подробнее. Проверить действующий канон дизайна.
- Один смысл — один ID иконки на всех новых экранах. Иконки меню пока не изменять.
- Не создавать копии услуг, страниц, справочников, роутеров или источников истины. Сначала сверить имеющиеся ID и реализации.
- Сохранить отдельный промпт дополнительного задания, задачи, подзадачи и этапы для будущих версий.
- Проверить дубли страниц, старые экраны и неправильную работу переходов.
- Работать поэтапно, сохранять контрольные точки, чтобы продолжить после обрыва связи.

## Минимальные критерии качества

- [ ] Уникальные ID и нормализованные названия, отсутствуют дубли существующих услуг.
- [ ] Каждая связь указывает на существующую услугу/профессию/оборудование.
- [ ] Разделены необходимые возможности, вспомогательные инструменты и альтернативные способы доступа.
- [ ] Оборудование принадлежит мастеру / доступно в СТО / арендуется — отдельные состояния.
- [ ] Синонимы клиента ведут к автоуслуге; двусмысленность вызывает выбор уточнения кнопками.
- [ ] Не выдавать гипотезы запросов за наблюдавшийся спрос.
- [ ] Для цен и наличия есть ссылка, время проверки, валюта и география; неизвестные значения остаются неизвестными.
- [ ] Иконки меню сохранены; одинаковые понятия новых карточек используют одинаковую иконку.
- [ ] Для визуальных карточек задана картинка отдельно от иконки; отсутствующие изображения явно отмечены.
- [ ] Основной сценарий услуг/оборудования доступен кнопками на телефоне и планшете.
- [ ] 4 шага заявки клиента сохранены; вложенные окна не увеличивают счётчик.
- [ ] Второй круг переходов проходит без вечного loading/skeleton и route_*_load_failed.
- [ ] Runtime-проверки не считать PASS по одному чтению исходников.

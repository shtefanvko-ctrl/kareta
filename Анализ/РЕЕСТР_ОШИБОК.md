## Приоритет и состояния

P1 — влияет на правильность сценария/сохранение либо блокирует проверенный выпуск. P2 — неполнота функции или доказательств. P3 — кандидаты на очистку после проверки. ## Что не следует объявлять ошибкой без доказательств

Наличие legacy js/app.js и js/db.js не доказывает их одновременное исполнение с новой SPA. Удаление требует анализа входов и загрузки. В проверенном serviceManagement registry CSS уже подключён: прежнее предположение о пустом styles не подтверждается текущим исходником. Старый тезис об undefined time при submit также не переносится на прочитанный актуальный request.js.

## Как закрывать запись

Для каждого исправления записывать точный SHA, затронутые файлы, реально выполненную проверку, результат и оставшиеся зависимости. Не закрывать E02/E12/E13/E14 по одному наличию коммита. При интеграции обновить snapshot PR-lanes: в предыдущем чтении PR #31 затрагивал work_feed, PR #35 — catalog/registry/SW, PR #34/#32 — lazy/perf контракты. Их актуальные головы проверить перед переносом.

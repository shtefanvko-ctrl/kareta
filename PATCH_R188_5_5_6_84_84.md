# R188.5.5.6.84.84 — First Paint Waterfall Cut

Base: `R188.5.5.6.84.83`
Target: `R188.5.5.6.84.84`
Mode: overlay patch, NO_ASSETS compatible.

## Что изменено

### 1. Убран второй последовательный DB/version ping

До этого cold boot делал отдельный `verifyRuntimeVersion()` запрос `api/db.php?action=ping`, а затем `warmSession()` снова запускал `KaretaProductionGuard.check({fast:true})`, который выполнял тот же public DB/version probe.

Теперь единственный fast probe запускается внутри `warmSession()` параллельно с Identity и legacy session reads. Его snapshot сохраняется в `state.bootGuardSnapshot`, а `verifyRuntimeVersion()` использует уже полученный `assetVersion` без нового HTTP round-trip.

Version mismatch остаётся fail-closed через `resetServiceWorkerRuntime('server-app-mismatch', ...)`. Stale Service Worker по-прежнему обрабатывается как handoff без повторной загрузки документа.

### 2. Lazy route assets загружаются параллельно с session hydration

Для исходного deep-link до ожидания сессии определяется только статический route key. Если маршрут lazy, его release-scoped CSS/JS начинается через `routeAssetLoader.ensureRoute()` сразу, пока параллельно выполняются DB/Identity/legacy session reads.

Никакие защищённые API/data requests до подтверждения сессии не выполняются — warmup загружает только статические CSS/JS из текущего release.

После session/role resolution:

- если итоговый route совпадает с prewarm route — boot переиспользует уже идущий/готовый promise;
- если route изменился из-за роли/onboarding gate — загружается правильный route;
- если ранний warmup завершился ошибкой — выполняется обычный fail-closed retry перед render.

Таким образом `routeRuntime.transition(... source:'boot')` по-прежнему выполняется только после подтверждённой route readiness.

### 3. Убран route-specific churn в тексте preloader

На 68% используется нейтральное `Загрузка интерфейса…` вместо динамического текста с названием раздела. Это не меняет route logic, но убирает визуальный скачок названия страницы на коротком lazy-load этапе.

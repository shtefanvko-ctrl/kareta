# R188.5.5.6.84.80 — Commissioning OTP Runtime Fix

## Root cause fixed

R188.5.5.6.84.79 configured production commissioning OTP as manual-off (`otp_temp_static_enabled=true`, empty `otp_temp_static_until`) but `KaretaChallengeService::temporaryStaticMode()` treated an empty deadline as inactive. This caused `effectiveTransport()` to fall back to production webhook and could return `provider_not_configured`/502 even though the release claimed that code `0000` was active.

## Changes

- Empty `otp_temp_static_until` now means **active until explicitly disabled** when `KARETA_OTP['temporary_static']` is true.
- Optional non-empty deadlines still expire normally.
- `KARETA_OTP_TEMP_STATIC_ENABLED=0` still immediately returns production to fail-closed webhook mode and removes the test code.
- Added an executable regression which boots production config and checks the private `temporaryStaticMode()` result through Reflection for manual-off, disabled, and expired modes.
- Asset and Service Worker releases advanced together to `188.5.5.6.84.80`.
- The historical 84.79 regression now checks 84.79+ release parity instead of freezing the project at 84.79.

## Protected

- `index.php` unchanged.
- `js/next/smart_action_hub.js` unchanged.

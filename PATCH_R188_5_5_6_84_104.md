## P0 — providers.detail 500 recovery

- Hardened `api/db.php?action=providers.detail&type=master&id=...` against production schema drift.
- `kareta_masters_catalog_payload()` no longer makes Master profile availability depend on STO-only tables.
- `sto_master_links`, `service_offers.availability_status`, offer totals and STO catalog blocks are schema-guarded/fail-soft.
- Public provider detail now isolates optional blocks: services, reviews, works, news, wall and social state.
- If the aggregated catalog fails, provider base data falls back to direct `masters` / `sto_profiles` lookup.
- Existing UI contract is preserved by normalizing public offers back to `service_id`, `service_name`, `service_icon`, duration/warranty aliases.
- Invalid provider type returns 422 instead of entering an undefined query path.
- Added regression `tools/test_provider_detail_failsoft_84_104.js`.

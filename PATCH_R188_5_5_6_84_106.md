# KARETA.KZ — R188.5.5.6.84.106 — MASTER UI FINAL

## Goal

Bring the complete Master interface to one visual and technical system without changing business logic, API contracts, or the database.

Development rule for all follow-up changes:

`route -> role -> component -> page`

A page-specific CSS fix is not allowed until the defect has been classified through those four levels.

## 1. Route / cascade

- `#/cabinet/settings` no longer receives `master_runtime.css` as a route exception. Cabinet functionality stays under `cabinet_runtime.css`; the Master appearance is applied by role.
- `masterSurfaceContract` is the final `cascade:last` layer for:
  - `#/master`
  - `#/master/schedule`
  - `#/master/exchange`
  - `#/services/manage`
  - `#/master/profile`
  - `#/master/wall`
  - `#/master/works`
  - `#/master/reviews`
  - `#/cabinet`
  - `#/cabinet/settings`
  - `#/orders`
  - `#/chats`
  - `#/parts`
  - `#/community`
- Shared routes keep their own functional CSS. Master appearance is not copied into them.
- `client_guard_postlude.css` may load for generic routes, but the late Master role layer owns the final Master geometry.

## 2. Role layer

Added `css/next/master_role_skin.css`.

It applies through `html[data-user-role="master"]` and normalizes the shared working routes:

- Parts
- Cabinet / Settings
- Orders
- Chats
- Community

It owns only role presentation: content width, page geometry, headers, toolbars, cards, typography alignment and mobile gutters.

## 3. Component foundation

Added `css/next/master_ui_foundation.css`.

Canonical Master tokens now include:

- colors / surfaces / lines;
- semantic status colors;
- content width and spacing;
- radii: 12 / 16 / 20 / 24;
- typography scale;
- button states;
- dialog geometry;
- mobile dialog safe areas;
- loading / empty / error / offline states.

Legacy Master variables are temporary aliases to the canonical token layer rather than separate sources of truth.

## 4. Buttons

Runtime Master pages now emit the `k-btn` API.

`master_schedule.js` no longer emits `k-button`.

Legacy `.k-button` selectors remain only as a compatibility bridge in the common component foundation while older modules are migrated.

## 5. Dialogs

Existing Master dialogs now inherit one common geometry and one mobile rule:

- 24px desktop dialog radius;
- common backdrop;
- common close control geometry;
- `100dvh` mobile mode;
- safe-area top/bottom handling;
- scrollable body with protected footer.

Specialized dialog classes retain content/behavior only.

## 6. Mobile navigation

`css/next/master_mobile_nav.css` is now the single owner of Master bottom navigation geometry.

Contract:

- exactly 6 slots;
- `Главная / Биржа / Услуги / Запчасти / Аккаунт / Ещё` remains unchanged;
- 22px icon boxes;
- stable badge positioning;
- 10px labels, 9px only at <=380px;
- no 8px labels;
- no `!important` in the Master navigation component;
- bottom safe-area is respected.

The obsolete `master_orders_dedup.css` five-column override is retired and removed from the active/eager cascade and boot bundle.

## 7. Icons

System close/search actions on Master routes and shared Master working routes use `KaretaUIIcons` instead of literal `×` / `⌕` glyphs.

The central icon registry was extended with `cart` and `camera` so Parts/Community do not need local Unicode fallbacks for these actions.

## 8. Owner surfaces

Source CSS for Profile / Wall / Works / Reviews was migrated instead of being covered by another override:

- owner headers use the flat Master Page Header language;
- H1 uses the Master title token;
- Reviews no longer owns a 2400px content width;
- Wall no longer makes the whole mobile page edge-to-edge;
- main cards use the shared radius scale;
- Works status colors use semantic Master status tokens.

Public Master surfaces remain separate from Owner Master surfaces.

## 9. Shared page wrapper

`page_ui.js` now recognizes Master workspace state from `data-user-role="master"` with navigation-context fallback.

Community receives `k-master-page k-master-surface-page` only for the Master role.

## 10. Generated bundles

- `master_runtime.css` rebuilt from its seven canonical sources and passes `--check`.
- `runtime_boot_bundle.css` contains the current `master_mobile_nav.css` source and no longer contains the retired five-column dedup layer.
- Boot JS bundles rebuilt after Page UI / icon registry changes.

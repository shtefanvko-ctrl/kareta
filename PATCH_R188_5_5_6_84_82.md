# R188.5.5.6.84.82 — Critical JS Grouping + Single-Roundtrip Session Bootstrap

## Scope

Performance/reliability patch over R188.5.5.6.84.81. No UI redesign and no route semantics change.

## Boot JavaScript

- Canonical eager source modules remain 72 and are retained under `scriptSources` for audit/build integrity.
- Browser atomic boot requests are reduced from 72 JS resources to 11 resources:
  - 5 small early bootstrap modules;
  - 5 generated ordered bundles under `js/boot/`;
  - `app_next.js` as the final boot module.
- Generated bundle order is byte-for-byte derived from canonical source files by `tools/build_boot_js_bundles.js`.
- `tools/build_boot_js_bundles.js --check` fails if any generated bundle is stale after a source change.
- Raw eager JavaScript source: 629,747 bytes.
- Boot transport JavaScript: 633,407 bytes (source markers add a small raw overhead).
- Sum of gzip-compressed resources in the local measurement: ~191,157 bytes -> ~165,190 bytes.
- Request count: 72 -> 11 (about 84.7% fewer boot JS requests).

## Visible progress

`app_preloader.atomicProgress()` now establishes its baseline when `app_preloader.js` itself becomes available. Files that completed before the preloader can execute no longer cause an immediate `4% -> 20/30%` jump after request grouping. The atomic phase now advances from 4% only across the remaining boot transport.

## Session / Identity critical path

Previous visible boot performed these reads serially:

1. DB/version ping;
2. Identity health/schema check;
3. Identity current session;
4. Context list;
5. legacy compatibility session.

R188.5.5.6.84.82 changes the visible boot to one concurrent read wave:

- fast DB/version probe;
- Identity current session;
- legacy compatibility session.

`identity_session.php?action=current` now returns `contexts`, `accountTypes`, `currentContext`, `capabilities` and `deniedCapabilities` together. `identity_frontend.js` consumes that response directly and keeps the old `/api/context.php?action=list` only as compatibility fallback for an older backend.

The full Identity schema health check is retained, but it runs after first paint and no longer blocks the visible 0 -> 100 boot.
